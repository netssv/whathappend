# Technical Maturity Roadmap — WhatHappened v3.2.1

**Role:** Staff Engineer / Technical Lead
**Scope:** Extension Hardening, Contributor Readiness, CI/CD, Security Audit Prep

## ✅ Completed Priorities (v3.2.x)

The following high-risk items and structural refactors have been successfully implemented:

- **P1 — `cleanForPipe()` Adversarial Test Suite:** Built adversarial tests to prevent XSS/ANSI injection via pipeline routing.
- **P2 — Command Manifest Validation:** `dev-lint.js` now strictly validates the `COMMAND_MANIFEST` structure.
- **P3 — CI Workflow:** `.github/workflows/ci.yml` is active, executing tests, linting, and integrity checks on every PR.
- **P4 — DOMPurify Integrity Lock:** `SHA-256` integrity check for `dompurify.min.js` added to the build and CI lifecycle.
- **D4 — Batched Output Engine:** Resolved the "parted output" issue by implementing a `requestAnimationFrame` chunked writer, preventing UI freezes during high-volume DNS data dumps.
- **S1 — ANSI Stripping:** Display-layer safety net (`stripAnsi`) is active.
- **S4 — Threat Model:** `docs/core/threat-model.md` added.
- **D1 — Command Names Decoupling:** `parser.js` now imports a static array (`command-names.js`) auto-generated by the linter, achieving zero transitive dependencies and fixing the cold-start issue.
- **DX1 — Contributing Guide:** `CONTRIBUTING.md` created to outline code standards and the 3-step command addition pattern.

## 🟠 Pending Technical Debt

While major blockers have been cleared, the following items remain as technical debt that must be addressed:

### D2 — 200-Line Module Limit Violations (✅ Resolved)
All modules now strictly comply with the 200-line architectural limit. `header-block.js` was split into `-core.js` logic and UI representation, while remaining files were condensed via code optimizations.

### D3 — `HELP_CATEGORIES` Key Derivation is Fragile (✅ Resolved)
**Fix:** Added an explicit `key` field to each definition file in `defs/*.js` and updated the UI builder to consume it directly, preventing derivation collisions.

### MV3-1 — SW Reconnection Protocol (✅ Resolved)
**Fix:** Implemented a continuous heartbeat pattern `setInterval` in `terminal-main.js` that pings the `router.js` service worker. This resets the extension's inactivity timer and guarantees the background script remains active during extended terminal sessions.

## 🟢 Long-Term Architecture Evolution

These items are considered future-facing architecture tasks (v3.2+):

### L1 — Command Schema Validation
Replace implicit manifest structure with a formal validation schema at load time.

### L2 — Command Output as Typed Objects
Transition from string-based output rendering (the 3-Part Output Standard) to returning structured data objects. This eliminates Regex-based ANSI stripping entirely during pipeline routing.

### L3 — Plugin/Extension API
Implement a secure, user-facing plugin system allowing external contributors to inject commands at runtime.
